# Chunk 3: Chat Interface & Message Stream

#react-native #ui #animation #ux #chat #components

## What this chunk does
Constructs the full mobile messaging interface (`ExpertChatScreen.jsx` and its supporting components). It displays conversation histories with sender-specific visual styling (User blue bubbles on right; AI consultant dark slate cards with engineering badges on left; Human engineer gold/navy cards), quick starter prompt chips (setbacks, pile depth, cost per sqft), an interactive message input bar, typing indicator, and clear conversation controls.

## Why it's needed
A backend or service layer is useless without an intuitive, accessible user interface. Landowners need a messaging environment that clearly differentiates between preliminary AI advice and licensed human recommendations, with fast shortcuts so they don't have to type lengthy engineering formulas on mobile keyboards.

## Builds on
- `Chunk 1 (chat-state-and-data-contracts)`: Uses `getChatHistory()`, `appendChatMessage()`, and `clearChatHistory()` for persistent thread rendering.
- `Chunk 2 (ai-expert-service-and-context)`: Calls `queryAiCivilExpert()` to generate contextual engineering responses when a user submits an inquiry.

## Key concepts
1. **Polymorphic Message Bubbles**:
   - `User`: Clean right-aligned blue bubble (`#2563eb`).
   - `AI Consultant`: Left-aligned slate bubble (`#1e293b`) with robot/blueprint badge and markdown support.
   - `Human Engineer`: Left-aligned premium card with engineer avatar, IEB credential badge, and official response styling.
2. **Context Banner**: A dismissible top card showing the active building specs currently imported from Feasibility/Designs (e.g. *"Discussing: 6 Stories • 4.0 Katha plot under RAJUK"*).
3. **Quick Discussion Starter Chips**: Horizontal scroll of 1-tap inquiries allowing landowners to immediately explore building code questions.
4. **Escalation Pill**: If an AI response flags `isEscalationPrompt: true`, a high-visibility button appears below that message: *"👨‍💼 Consult Licensed Engineer"*.

       - messages: array (loaded via getChatHistory)

## Storage Under the Hood
Each message added to the screen automatically triggers `AsyncStorage.setItem('@civilhub_chat_messages_v1_default', JSON.stringify(messages))`, ensuring zero data loss if the user switches tabs or backgrounds the app.

## The Edge Case & Error Matrix

| Input / Condition | Failure Mode | Handled By | Resulting Behavior |
|-------------------|--------------|------------|---------------------|
| User rapidly presses Send button | Duplicate queries sent | Disables Send button while `isTyping === true` | Prevents race conditions and duplicate messages |
| Empty text submitted | Blank bubble rendered | `inputText.trim()` guard | Ignores send action if input contains only whitespace |
| Very long engineering text | Overflowing layout / unreadable bubble | Bubble `maxWidth: "85%"` with `flexWrap: "wrap"` | Wraps cleanly with comfortable padding |
| Keyboard pops up on mobile | Input field obscured | `KeyboardAvoidingView` with `behavior="padding"` | Slides input bar upward smoothly above keyboard |

## Why NOT Do It This Other Way? (Anti-Patterns & Alternatives)
- **Anti-Pattern (Unbounded FlatList without Keyboard Avoidance):** Without `KeyboardAvoidingView` and `contentContainerStyle` padding, typing on physical smartphones covers the input field completely, making it impossible to see what is being typed.
- **Anti-Pattern (Generic Text Bubbles without Sender Distinction):** If AI advice and Human Engineer advice look identical, landowners cannot distinguish between AI estimations and legally binding professional consultations.

## How it works
`ExpertChatScreen.jsx` fetches the saved message history on mount and renders a vertical scrollable list. Each item is passed to a bubble renderer that styles it based on `senderRole`. Above the input bar, a row of quick chips allows one-tap question submission. When a message contains `isEscalationPrompt: true`, an action pill invites the user to open the Verified Engineer Directory.

## Gotchas / trade-offs
- On web, `ScrollView` does not always automatically snap to the bottom on new elements; an explicit `scrollViewRef.current?.scrollToEnd({ animated: true })` inside a short `setTimeout` ensures reliable auto-scrolling across both Web and native devices.
