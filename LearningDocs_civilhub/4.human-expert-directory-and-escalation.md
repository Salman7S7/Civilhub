# Chunk 4: Human Expert Directory & Escalation

#directory #human-in-the-loop #modal #profiles #escalation

## What this chunk does
Implements the **Verified Human Engineer Directory Modal (`ExpertDirectoryModal.jsx`)**. It allows landowners to browse accredited Bangladeshi civil engineers and architects (IEB/IAB registrations, years of experience, ratings, specialties like Structural, Geotechnical/Soil, and RAJUK planning). When a landowner selects an engineer, it provides one-tap consultation handoff: sending a formal escalation briefing (with active plot & story specs) into the chat thread and returning a simulated welcome greeting from that engineer.

## Why it's needed
While AI provides instantaneous preliminary guidance, Bangladeshi law and municipal bylaws (RAJUK, CDA, Pourashavas) legally mandate licensed IEB engineers for structural drawings, soil test interpretation, and building permit seals. The directory bridges the gap between AI triage and real-world professional accountability.

## Builds on
- `Chunk 1 (chat-state-and-data-contracts)`: Uses `VERIFIED_EXPERTS`, `getAvailableExperts()`, and `appendChatMessage()` to record the escalation event.
- `Chunk 3 (chat-interface-and-message-stream)`: Plugs directly into the `onOpenExpertDirectory` and escalation button handlers on `ExpertChatScreen.jsx`.

## Key concepts
1. **Accredited Engineer Badges**: Visually highlighting verified credentials (e.g. `PEng`, `MIEB`, `IAB`, `RAJUK Enlisted`).
2. **Specialty Filtering**: Filter chips for *All*, *Structural*, *Architectural/RAJUK*, and *Soil/Geotechnical*.
3. **Contextual Escalation Handoff**: When connecting with an engineer, the app automatically posts a structured briefing message into the conversation thread (e.g. *"Consultation Request: 7-story RCC design on 4.5 Katha plot in Dhaka"*), followed by an automated welcome acknowledgment from the chosen engineer.

## The Edge Case & Error Matrix

| Input / Condition | Failure Mode | Handled By | Resulting Behavior |
|-------------------|--------------|------------|---------------------|
| Engineer currently unavailable | User expects immediate live chat | Status badge (`isAvailable: false`) | Shows "Busy / Offline" badge and sends consultation request for callback |
| No active project context | Generic consultation | Null check on `activeContext` | Connects general inquiry without broken empty context strings |
| Modal closed without selection | Unwanted state update | `onClose` cancellation | Preserves existing chat without creating ghost messages |

## Why NOT Do It This Other Way? (Anti-Patterns & Alternatives)
- **Anti-Pattern (External Link to WhatsApp / Phone only):** Ejecting the user outside the app breaks conversation continuity and loses the plot parameters they spent time entering. An in-app handoff preserves context.
- **Anti-Pattern (Unverified Generic Usernames):** Using generic names like "User123" ruins trust. Real IEB/IAB license numbers give landowners confidence.

## How it works
`ExpertDirectoryModal.jsx` renders engineer profile cards featuring their avatar, IEB credentials, specialties, years in practice, and rating. Tapping "Consult" injects the expert into the chat history, closing the modal and displaying their personalized response bubble.

## Gotchas / trade-offs
- In a production backend, human messages would be routed via WebSockets/Push notifications to the engineer's portal. In our mobile prototype, simulated instant handoff confirms the data contracts work end-to-end.
